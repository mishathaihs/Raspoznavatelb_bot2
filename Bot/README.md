# GoogleDOCBOT

Телеграм-бот для обработки актов и накладных с интеграцией Google Sheets и Google Drive.
Поддерживаются акты выполненных работ и товарные накладные.

## Возможности

- Принимает PDF и изображения актов/накладных.
- Выполняет OCR (pytesseract) при необходимости и извлекает текст.
- Передаёт текст в LLM (OpenAI) для получения структурированных данных.
- Записывает данные по позициям в Google Sheets и связывает строки с файлом.
- Загружает файл на Google Drive с переименованием по шаблону `номер_дата_контрагент`.
- Позволяет удалять ранее загруженные документы (и строки, и файл).

## Требования к качеству документа

- Форматы: **PDF / JPG / PNG**.
- Скан и PDF: разрешение от **200–300 dpi**.
- Фото: ширина кадра **1500–2000 px**, хорошее освещение, без бликов и сильного наклона.
- Текст не меньше 10–12 pt, документ целиком в кадре.

## Подготовка окружения

1. Склонируйте репозиторий и создайте виртуальное окружение Python 3.10+.
2. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
3. Убедитесь, что на сервере установлен Tesseract OCR и необходимые языковые пакеты (`rus`, `eng`).

## Настройка Google API

1. Создайте проект в Google Cloud Console и включите API **Google Drive** и **Google Sheets**.
2. Настройте экран OAuth Consent (External) и добавьте свой Google-аккаунт в тестовые пользователи.
3. Создайте OAuth Client ID типа **Desktop app** и скачайте файл с секретами. Положите его рядом с проектом под именем `credentials_drive.json` (или укажите другой путь в настройках).
4. Выдайте аккаунту, под которым пройдёте OAuth, права редактора на целевую таблицу и папку Google Drive.
5. Откройте браузерный OAuth-поток один раз командой `python scripts/init_drive_oauth.py`. После успешной авторизации появится файл токена (`token_drive.json` по умолчанию).

Если нужно сохранять строки в таблице даже при ошибке Drive, установите `ALLOW_SHEETS_WITHOUT_DRIVE_FILE=true` — сводка укажет, что файл не сохранён.

## Настройка OpenAI

1. Создайте API-ключ в [OpenAI](https://platform.openai.com/).
2. Сохраните ключ в переменной `OPENAI_API_KEY`.

## Настройка Telegram

1. Создайте бота через @BotFather и получите токен.
2. Задайте переменную `TELEGRAM_BOT_TOKEN`.

## Файл `.env`

Создайте `.env` в корне проекта (можно начать с шаблона [.env.example](.env.example)) и заполните значениями:

```env
TELEGRAM_BOT_TOKEN=123456:ABCDEF
OPENAI_API_KEY=sk-...
GOOGLE_SHEETS_SPREADSHEET_ID=1gibKA4OwUb6RQKqjSpYcOwDjEpfuedLnngpJsUe02Y0
GOOGLE_SHEETS_WORKSHEET_TITLE=Лист1
GOOGLE_AUTH_MODE=oauth
GOOGLE_OAUTH_CLIENT_SECRETS_FILE=credentials_drive.json
GOOGLE_OAUTH_TOKEN_FILE=token_drive.json
GOOGLE_DRIVE_FOLDER_ID=1cSpfZhp1UzgVlX53S1xCv7TG_Gdawn4y
ALLOW_SHEETS_WITHOUT_DRIVE_FILE=false
LOG_LEVEL=INFO
```

> Можно указывать как чистый `spreadsheetId`, так и полную ссылку на таблицу — бот извлечёт ID автоматически.

Если таблица ещё не создана или ID неверный, выполните `python scripts/bootstrap_project.py` — скрипт создаст новую таблицу, обновит `.env` и сообщит новый идентификатор. Расширенный чек-лист по настройке приведён в [docs/SETUP_GOOGLE_SHEETS.md](docs/SETUP_GOOGLE_SHEETS.md).

## Запуск

```bash
python main.py
```

Бот будет получать документы, отправленные в чат, и автоматически обрабатывать их.
При старте проверяется наличие обязательных переменных (`GOOGLE_SHEETS_SPREADSHEET_ID`, `GOOGLE_DRIVE_FOLDER_ID`). Если конфигурация неполная, бот завершит работу с понятным сообщением в логах.

## Структура Google Sheets

```
A: Номер по порядку
B: Тип документа
C: Дата документа (ДД-ММ-ГГГГ)
D: Номер документа (для акта без номера — Б/Н)
E: Контрагент
F: Наименование товара/услуги
G: Сумма позиции (с НДС) — два знака после запятой
H: Сумма НДС позиции — два знака после запятой
I: Ссылка на файл в Drive
```

> Если вы используете уже созданную таблицу из скриншота, задайте в `.env` те же значения `GOOGLE_SHEETS_SPREADSHEET_ID=1gibKA4OwUb6RQKqjSpYcOwDjEpfuedLnngpJsUe02Y0` и `GOOGLE_SHEETS_WORKSHEET_TITLE=Лист1`, чтобы бот писал данные в существующий лист.

Каждая позиция документа добавляется отдельной строкой. Для удаления используется `Номер по порядку`. При повторной отправке того же документа бот предложит заменить имеющуюся запись или оставить как есть.

### Частые ошибки

- **TelegramUnauthorizedError** при старте: проверьте, что в `.env` указан реальный `TELEGRAM_BOT_TOKEN` от вашего бота у @BotFather. Убедитесь, что в строке нет лишних пробелов/переводов строки или кавычек; проще всего переписать токен заново из BotFather и перезапустить процесс. Если проблема сохраняется, выполните в @BotFather `/revoke <username_бота>` → `/token` чтобы сгенерировать новый токен, обновите `.env`, перезапустите терминал (чтобы переменные окружения не перебивали `.env`) и снова запустите `python main.py`.
- **OAuth 403 access_denied** в браузере: в Google Cloud Console открой **APIs & Services → OAuth consent screen**, убедись, что статус **Testing**, и добавь свой Gmail в **Test users**. Авторизуйся тем же аккаунтом, затем снова запусти `python scripts/init_drive_oauth.py`.

## Удаление документов

- В сообщении после загрузки доступна кнопка «Удалить документ №N».
- Также можно вызвать `/delete N`.

## Ответы на вопросы из п.5 ТЗ

- **Обработка ошибок распознавания.** Сейчас бот пропускает нераспознанный документ: при ошибке OCR/LLM отправляет пользователю сообщение с просьбой перепроверить качество и отправить файл повторно. Ручного подтверждения/редактирования внутри бота нет.
- **Взаимодействие в Telegram.** Используется приветствие `/start` с инструкцией и inline-кнопками, а также кнопки под итоговым сообщением (удалить документ, обработать ещё один). Командный ввод ограничен `/start`, `/help`, `/delete` — основной сценарий через отправку файла.
- **Уведомления.** После успешной обработки бот присылает сводку (тип, номер, дата, контрагент, суммы, номер по порядку) и клавиши действий. При ошибках сообщает, что данные не записаны, и предлагает повторить попытку.
- **Мульти-файл.** Обработка ведётся по одному документу на сообщение. Чтобы загрузить несколько файлов, их нужно отправлять по очереди; пакетная загрузка одной командой не реализована.

## Логирование

Логирование выводится в stdout. Уровень задаётся переменной `LOG_LEVEL`.

## Примечания

- Запросы к Google API и OpenAI выполняются асинхронно через `asyncio.to_thread`, поэтому блокирующие вызовы не мешают боту.
- Для улучшения качества распознавания рекомендуется отправлять документы с хорошим разрешением.

## Пошаговый гайд по запуску на Windows 10 x64

1. **Предварительно**: Windows 10 x64, интернет, права установки, браузер для скачивания ПО.
2. **Установите Python 3.10+**: скачайте с python.org, включите галочку “Add Python to PATH”, проверьте `python --version`.
3. **Скачайте проект**: распакуйте ZIP или `git clone` в `C:\Projects\GoogleDOCBOT`.
4. **Создайте виртуальное окружение**:
   ```cmd
   cd C:\Projects\GoogleDOCBOT
   python -m venv venv
   venv\Scripts\activate
   ```
5. **Установите зависимости**:
   ```cmd
   pip install -r requirements.txt
   ```
6. **Поставьте Tesseract OCR** (UB Mannheim, `rus`/`eng`), проверьте `tesseract --version`; при необходимости добавьте `C:\Program Files\Tesseract-OCR` в PATH.
7. **Получите доступы**:
   - Telegram токен → `TELEGRAM_BOT_TOKEN`.
   - OpenAI API Key → `OPENAI_API_KEY`.
   - OAuth-секрет Google (Desktop): сохраните `credentials_drive.json` рядом с проектом; таблица и папка должны принадлежать аккаунту, проходящему OAuth, или быть ему доступны как «Редактору».
8. **Создайте `.env`** (пример выше).
9. **Выдайте токен**: выполните `python scripts/init_drive_oauth.py`, авторизуйтесь в браузере, убедитесь, что появился `token_drive.json`.
10. **Запуск** (в активном `venv`):
    ```cmd
    python main.py
    ```
    В консоли появятся INFO-логи старта.
11. **Тестирование**: в Telegram отправьте `/start`, затем PDF/JPG/PNG; бот вернёт сводку и кнопки для удаления и повторной обработки, а записи появятся в таблице и папке Drive.
